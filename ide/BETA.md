# Pulse (beta) 사용 안내

Windows x64용 RTL 설계·시뮬레이션 IDE입니다. 프로젝트 시작, RTL 편집, 테스트벤치 실행과 파형 확인을 한 앱에서 제공합니다.

## 설치와 시작

1. 기존 Pulse 창을 정상 종료하고 `Pulse-Setup-windows-x64-beta-20261016.exe`를 실행하세요.
2. 기본 설치 위치는 `%LOCALAPPDATA%\Programs\Pulse`입니다. 시작 메뉴에 Pulse가 등록되며 바탕화면 바로가기는 선택할 수 있습니다. 개발용 Node/npm이나 이 저장소는 필요하지 않습니다.
3. Pulse를 열고 **새 프로젝트** 또는 **기존 프로젝트 열기**를 선택하세요. 새 프로젝트는 빈 `rtl/`, `tb/`와 IDE 관리 설정을 준비합니다. 기존 폴더의 원본 RTL은 유지합니다.
4. 처음 여는 프로젝트는 내용을 확인하고 신뢰 여부를 직접 선택하세요. 신뢰하지 않은 폴더에서도 편집은 가능하지만 외부 도구 실행은 제한됩니다.

기존 설치판과 같은 제품 ID·설치 경로를 사용하도록 구성했습니다. Windows 설치된 앱/제어판의 이름은 **Pulse (beta)**입니다. 제거 시 프로젝트·사용자 설정·공유 개발 도구를 삭제하지 않습니다. 시스템 PATH와 파일 연결은 변경하지 않습니다.

## 시뮬레이션

1. 왼쪽 **Simulation** 아이콘을 선택하세요. 설정된 TB 폴더의 파일은 자동으로 목록에 반영되며, 추가·삭제 때문에 시뮬레이션이 자동 실행되지는 않습니다.
2. **TB 폴더 설정**으로 자동 추적할 폴더를 고르세요. 다른 위치의 코드는 **TB 파일 가져오기**로 프로젝트의 TB 폴더에 복사할 수 있습니다. 한 파일에 완성된 테스트 top이 여러 개면 각각 관리합니다.
3. **Simulation 설정**에서 필요한 소스·헤더 검색 폴더·테스트 제외 항목과 도구 상태를 확인하세요. IDE 관리 프로젝트의 `rtl.toml`은 앱이 관리하며 세부 조정도 이 화면에서 할 수 있습니다.
4. 도구가 없으면 설정에서 필요한 항목과 위치를 확인한 뒤 설치를 승인하세요. 기존 Verilator/C++·slang/Python·GTKWave는 검증 후 재사용합니다. 앱에는 이 도구들이 포함되지 않으며 첫 설치에는 네트워크가 필요합니다.
5. 테스트 행의 실행 버튼, 선택 실행, 전체 실행 또는 등록된 TB의 Explorer 실행 버튼/F5를 사용하세요. 결과의 로그·파형 버튼으로 확인합니다. 테스트 실패는 assertion 또는 `$fatal`로 표현하세요.

TB에 dump 코드나 C++ harness를 작성할 필요가 없습니다. 앱이 파형 기록을 관리합니다. 미저장 RTL은 실행 시작 시점의 복사본으로 사용하며 원본을 자동 저장하지 않습니다. 미저장 설정 파일은 먼저 정리해야 합니다.

## 편집과 파형

RTL 기본 템플릿과 현재 범위의 신호, 프로젝트 모듈·포트·package 추천을 지원합니다. 모듈 추천을 선택하면 빈 인스턴스 이름 위치로 이동하고 다음 Tab으로 포트 괄호 안으로 이동합니다. 프로젝트를 처음 분석하기 전이나 새로운 정의를 추가한 직후에는 의미 정보 준비 시간이 필요합니다.

내장 VCD 뷰어의 Signals에서 신호를 선택하고 드래그로 순서를 바꿀 수 있습니다. bus를 비트별로 펼치고 Cursor/Zoom range를 선택할 수 있습니다. 시간은 절대시간으로 표시하며 긴 값은 나누어 보여줍니다. Save view/Use as default로 테스트별 신호 구성을 저장합니다. FST는 생성할 수 있으며 표시는 GTKWave를 사용합니다.

실행 이력의 보관 소스·입력 비교·소스 차이로 당시 코드와 현재 코드를 구분합니다. PASS/FAIL과 현재 코드 변경 표시는 별개입니다. 파형 탭은 테스트 이름을 표시하고 여러 실행은 툴팁의 시각·ID로 구분합니다.

실행 중 Code↔Simulation 전환은 작업 상태를 유지합니다. 프로젝트나 앱을 닫은 뒤 마지막 Pulse 작업 공간·파형 탭·커서를 자동 복원하지는 않습니다. 최근 프로젝트, 실행 이력, 보관 소스·파형과 편집기의 미저장 복구는 별도입니다.

## 지원 범위와 검증 상태

- Windows x64·Verilator timing/assert·내장 VCD·외부 GTKWave를 지원합니다. Diagram/synthesis·자체 compiler/simulator·Marketplace/외부 확장 설치·Chat은 이번 베타 범위가 아닙니다.
- 내장 파형은 trace32MiB/신호10,000개/변화1,000,000개/선택32개 등 한도가 있습니다. 큰 결과는 GTKWave를 사용하세요. 내장 FST·enum 이름 표시와 대표 설계의 장시간 수용 등은 잔여 항목입니다.
- 실행 생성물은 `.rtl/` 아래에 모읍니다. 이 폴더를 삭제하면 기록·파형·보관 소스가 사라지므로 필요한 결과를 먼저 보존하세요. 중요한 소스와 설정은 Git으로 관리하는 것을 권장합니다.
- 최신 앱의 빌드·자동 회귀·배포 파일 검사와 설치 마법사/설치·업그레이드·제거/깨끗한 Windows 수용은 서로 다릅니다. 이번 설치판은 실제 설치 및 새 화면 검증을 완료했다고 표시하지 않습니다. 동봉 `PULSE-ACCEPTANCE.json`과 Setup manifest에 실제 범위를 기록합니다.

자세한 제공 범위는 [PRODUCT_SCOPE.md](PRODUCT_SCOPE.md), CLI 사용법은 [CLI.md](CLI.md)를 참고하세요. `PULSE-NOTICES.txt`와 Code-OSS/Chromium 고지는 보존해 주세요. 앱의 1.141.0 표시는 기반 Code-OSS 버전이며 이번 Pulse 배포는 `0.1.0-beta.20261016`입니다.

문제 제보 시 배포 파일 이름, 누른 버튼, 실행 로그와 최소 재현 RTL을 함께 알려주세요. 공유하면 안 되는 설계나 비밀 값은 제거해 주세요.
