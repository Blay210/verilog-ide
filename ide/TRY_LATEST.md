# 최신 Pulse 개발 버전 사용

현재 저장소에서 빌드된 최신 앱은 `Start-Pulse.cmd`를 더블클릭해 실행합니다. 공식 desktop bundle을 포함한 별도 로컬 앱이며 개발 소스 모드로 실행하지 않습니다. Node와 이 PC에 이미 준비된 실행 파일을 사용하고 이 실행 경로 자체는 설치를 수행하지 않습니다. 시작할 때마다 번들을 다시 만들거나 큰 Electron 파일의 전체 해시를 재계산하지 않습니다. 실행 준비 시간과 실제 창이 뜨는 시간은 별개입니다.

1. 열려 있는 Pulse 창을 정상적으로 닫은 뒤 `D:\Dev\verilog_ide\ide\Start-Pulse.cmd`를 실행합니다. 같은 프로필의 이전 프로세스가 남으면 새 코드 대신 기존 프로세스에 창 요청이 전달될 수 있습니다.
2. 앱에서 **File → 기존 프로젝트 열기…** 또는 **새 RTL 프로젝트…**를 선택합니다. 폴더가 열리지 않은 첫 화면에서도 프로젝트 진입 버튼을 제공합니다.
3. 기존 프로젝트에 `rtl.toml`이 없으면 발견된 소스/테스트벤치를 검토하고 프로젝트 준비를 완료합니다. 신뢰 요청은 사용자가 직접 판단합니다. 준비는 실행과 구분되며 자동 시뮬레이션하지 않습니다.
4. 왼쪽 **Simulation**에서 테스트 목록의 실행 버튼을 누릅니다. 성공한 결과의 파형 버튼으로 내장 파형을 엽니다. 테스트벤치에 dump 코드를 추가할 필요는 없습니다.
5. 실행 중 Code와 Simulation을 오갈 때 작업 상태가 유지됩니다. 새 사용자 정책에 따라 프로젝트/앱 종료 후 Pulse의 마지막 공간·파형 탭·커서는 자동 복원하지 않습니다. 최근 프로젝트와 실행 이력/보관 파형은 유지됩니다. 폴더가 없는 창은 별도의 프로젝트 시작 화면을 제공합니다.

Simulation 목록 위의 **TB 파일 가져오기**는 외부 파일을 프로젝트의 첫 번째 지정 TB 폴더(없으면 `tb/`)로 복사하고 등록합니다. 같은 이름의 파일은 덮어쓰지 않습니다. **TB 폴더 설정**은 프로젝트 안의 폴더를 자동 추적 대상으로 지정합니다. 해당 폴더에 파일이 추가·삭제되면 목록만 갱신되고 자동 실행하지 않습니다. include·소스·top, 동시 실행 수·태그, 제외 복원·도구는 **Simulation 설정** 팝업에서 조정합니다.

신뢰된 프로젝트에서 의미 분석이 준비되면 모듈·접근 가능한 신호·포트·프로젝트 패키지 이름을 추천합니다. 모듈 이름을 확정하면 빈 인스턴스 이름 위치와 포트 괄호 안으로 Tab 이동하며 입력할 수 있습니다. `패키지::`와 미연결 `.포트`는 전체 유효 후보를 받고 추가 입력에 따라 편집기가 추립니다. RTL 기본 설정은 snippet 입력 중에도 자동 추천을 제공합니다. 사용자가 자동 추천을 명시적으로 끈 설정은 존중합니다.

최신 분석 결과는 메모리에 유지하며 입력이 이어지면 변경을 모으고 잠시 멈추거나 구문을 마치면 분석합니다. 준비 중에는 예약어·현재 문서 신호의 보조 추천을 제공합니다. 처음 목록이 비었더라도 현재 입력 요청이 유지되면 정밀 결과 준비 후 자동 표시하므로 Ctrl+Space를 반복할 필요가 없습니다. Esc·커서 이동·포커스/공간 전환으로 취소했거나 요청이 오래된 경우는 다시 열지 않습니다. 수정 직후 정밀 후보의 준비 시간은 여전히 남으며 기본 보조 추천은 의미 분석과 구분합니다. [자동 추천 보완·검증](../docs/pulse-automatic-completion.md) 참조.

이 실행 방식의 프로필은 `ide/.dev/rtl-ide/profile`이며 별도의 내부 검증 프로필과 다릅니다. 설정/신뢰를 복사하지 않습니다. 2026-10-14 Setup/ZIP은 이번 보완 이전 코드입니다. 최신 Setup 산출물과 실제 검증 범위는 [2026-10-16 배포 기록](../docs/pulse-beta-20261016.md)에서 확인하세요.

코드 편집 후에는 분석 프로세스를 재사용하고 이전 모델을 새로 교체합니다. 취소한 추천 요청 때문에 다른 추천 작업까지 종료하지 않으며, 문서 버전이 맞는 결과만 표시합니다. 첫 정밀 조회의 중복 경로·scope 처리를 줄이고 Simulation 버튼·설정 화면은 첫 진입 때 구성합니다. 첫 모델과 정밀 조회 대기는 여전히 남으며 실제 앱 시작/입력 속도는 직접 체험 후 확인합니다.

현재 선택된 경로는 `ide/.dev/latest-launch.json`의 `executable`에서 확인할 수 있습니다. 별도 `.dev/pulse-bundled-*` 디렉터리의 앱이며 기존 `VSCode-win32-x64`나 Setup을 덮어쓰지 않습니다. native code cache는 이 코드의 고유 hash로 구분하고 기존 신뢰/프로필은 그대로 사용합니다.

개발자 재현: `npm run build:runtime`·`npm run build:language`·필요한 본체 타입 검사를 마친 뒤 `node scripts/prepare-local-bundle.mjs`를 실행합니다. 새 출력 디렉터리의 `.pulse-build.json`이 PASS일 때 `node scripts/latest-launch.mjs prepare-bundled <출력 디렉터리>`로 선택하고 `node scripts/latest-launch.mjs --check`로 확인합니다. `prepare`는 이전 소스 개발 모드를 명시적으로 선택하는 fallback이므로 현재 built 앱을 체험할 때 실행하지 않습니다. 준비된 파일의 크기/수정 시각이 달라졌으면 시작을 중단하며 이는 로컬 준비 검사이지 배포물 전체 hash 검사 대체가 아닙니다. [성능 개선과 남은 한도](../docs/pulse-performance-final.md) 및 [최신 Setup 검증 기록](../docs/pulse-beta-20261016.md)을 참고하세요. 배포 생성은 사용자 요청이 있을 때만 하며 실제 설치/화면 확인과 구분합니다.
