# 독립 RTL IDE

Code-OSS 1.141.0 기반 독립 RTL IDE를 개발 중입니다. Code/Simulation 작업 공간과 공통 하단 패널, Simulation 홈의 테스트 목록·전체/선택/개별 실행·취소·로그·실행 이력·코드 변경 표시·실행별 내장 VCD 파형 탭을 구현했습니다. 앱의 Node 실행 서비스는 IDE 자체 Core와 Verilator를 사용합니다. 아직 베타/배포 버전이 아닙니다.

완료된 결과 행의 **파형** 버튼으로 열고 **Simulation 홈**으로 목록에 돌아갑니다. 이전 실행 파형은 새 결과와 별도 탭으로 보존합니다. 신호를 고르고 **Save view…**로 여러 보기를 저장하며 **Use as default**로 다음 파형의 기본 보기를 지정합니다. 순서·표현 형식·색·bus 펼침도 저장합니다. **⋯**에서 이름 변경/삭제가 가능합니다. 설정은 `.rtl/waveform-views/`에 저장됩니다. 내장 FST 표시와 enum 소스 매핑은 아직 연결하지 않았습니다. GUI 실행은 실행 버튼을 누른 시점의 저장된 코드와 미저장 RTL 편집 내용을 사용합니다.

**파형 코드를 작성할 필요가 없습니다.** IDE/CLI가 같은 Verilator driver로 VCD/FST를 자동 기록하며, 원본 테스트벤치를 수정하지 않습니다. `rtl.toml`의 `waveform="none"`으로 기록을 끕니다. 생성 파일은 `.rtl/runs/<test>-<runId>/rtl_<top>_<고유값>.vcd` 또는 `.fst`에 보관하고 UI에서는 테스트 이름과 실행 이력으로 관리합니다. 기존 `$dumpfile/$dumpvars`는 유지되어 별도 파일을 만들 수 있지만 결과의 파형 버튼은 IDE가 기록한 파일을 엽니다. 기존 dump 범위/켜기·끄기는 별도 사용자 파일에만 적용되며 IDE는 전체 모델을 기록합니다.

개발 명령과 재현 방법은 [DEVELOPMENT](DEVELOPMENT.md)을 확인하세요. 제품 결정·전체 계획은 저장소 공통 docs에서 관리하며 runtime/build 입력이 아닙니다.

임시 제품 identity와 Chat/확장 설치 정책을 적용하는 H1 후속 구현은 [PRODUCT-POLICY](PRODUCT-POLICY.md)에 기록합니다. 코드 제거와 UI/CLI 종단 수용이 끝난 상태는 아닙니다.

모든 코드·설정·의존성·테스트는 ide 내부에 둡니다. vsix/상위 소스 import/load·file dependency·symlink/path alias를 금지합니다. 필요한 Core/Verilator 코드는 출처·MIT 라이선스를 보존해 수동 이식하고 IDE에서 독립 관리합니다. 외부 extension/Chat/첫 앱 Diagram은 제외합니다. 자체 엔진은 별도 논의 후 진행합니다.

테스트 행의 실행 이력에서 이전 결과를 고르면 로그·파형 버튼이 그 실행을 엽니다. **보관 소스**에서는 해당 실행에 사용한 RTL/package/header를 골라 읽기 전용으로 열 수 있습니다. 탭의 보관 runId와 미저장 입력 설명으로 현재 소스와 구분하며, 원본이 바뀌거나 삭제돼도 실행 당시 복사본을 확인합니다. 테스트 이름 버튼은 현재 테스트벤치 파일을 엽니다. △ 코드는 최근 실행 이후 저장된 입력 변경, △ 미저장은 현재 편집 중인 변경을 나타냅니다. 이전 실행 선택이나 코드 변경으로 이미 열린 파형은 교체되지 않습니다.

RTL 파일을 열면 내장 Verilog/SystemVerilog 문법 색상·예약어/시스템 함수 자동완성을 사용할 수 있습니다. `module`에서 Tab하면 이름→포트→본문으로 이동하며 `package`, `case`, `begin`, `always*` 템플릿도 제공합니다. 기본 편집에는 도구 설치나 신뢰 승인이 필요 없습니다.

신뢰된 프로젝트와 검증된 기존 slang 11.0.0 도구가 있으면 모듈·미연결 포트·접근 가능한 스코프의 신호 추천, 함수 인자, module 의미 색상·정의 이동·RTL 진단도 연결됩니다. 미저장 RTL/package 변경은 분석에 반영하며 소스는 자동 저장하지 않습니다. 언어 상태는 상태 표시와 **RTL: Language Status**에서 확인하고 **RTL: Retry Analysis**로 재시작합니다. `rtl.editor.semantic`으로 끌 수 있습니다. TOML 설정 오류는 언어 상태/로그로 안내합니다.

Simulation 홈의 **도구 설정**에서 기존 도구를 검증하고 부족한 구성 요소의 설치 계획을 확인할 수 있습니다. **설치**를 승인했을 때만 시작하며 진행 알림에서 취소할 수 있습니다. 실패 시 재시도/로그 보기를 제공합니다. 언어 상태 메뉴의 **언어 도구 설정**도 같은 흐름을 사용합니다. 공유 저장소는 프로젝트 밖이며 시스템 PATH는 변경하지 않습니다.

GUI의 개별·선택·전체/Explorer 실행은 등록된 테스트와 실행 당시 RTL/header 편집 내용을 snapshot으로 보존합니다. 파일을 자동 저장하지 않으며, 결과/이력의 **미저장 입력** 표시에서 사용한 파일을 확인할 수 있습니다. 이후 편집은 진행 중인 실행에 반영되지 않습니다. 미저장 rtl.toml은 먼저 검토해야 하고, 미저장 RTL은 현재 UTF-8/UTF-8 BOM을 지원합니다. CLI 기본 실행은 저장된 파일을 사용합니다. 최근 실행과 현재 편집 내용이 같으면 **현재 편집 내용 일치 · 미저장**, 이후 수정하면 **△ 실행 후 변경됨**으로 표시합니다. 저장된 파일과의 비교는 tooltip에서 분리합니다. 이전 실행을 선택한 뒤 **입력 비교**를 누르면 해당 기록과 현재 입력을 비교합니다. 이후 편집하면 **다시 비교**로 표시합니다. **소스 차이**에서 보관 원문과 현재 파일을 나란히 볼 수 있으며, 삭제된 현재 파일을 자동 생성하지 않습니다. 신뢰하지 않는 프로젝트에서는 실행/의미 분석/도구 설정을 잠그며 기본 편집과 파형 보기 설정은 유지합니다. 도구 설정·새 환경 설치 수용 범위는 [H3J 도구 설정 기록](../docs/ide-h3j-tool-setup.md)에 기록합니다.
